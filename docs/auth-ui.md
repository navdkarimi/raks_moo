# فرم ورود و آزمون مرورگر

## ساختار

- `/login`: ورود شماره، درخواست کد، تأیید، شمارش معکوس، ارسال مجدد و ویرایش شماره.
- `/account`: دریافت حساب جاری از API، نمایش شمارهٔ تأییدشده و خروج.
- `features/auth/auth-client.ts`: ارتباط با API، بررسی قرارداد پاسخ و خطاهای قابل‌نمایش.
- `features/auth/login-form.tsx`: حالت‌های فرم و کنترل درخواست هم‌زمان.
- `features/auth/account-panel.tsx`: نمایش حساب و مدیریت خطای دریافت یا خروج.
- `auth-shell.tsx` و `auth-controls.tsx`: ظاهر و اجزای مشترک.

توکن نشست در localStorage یا state فرانت ذخیره نمی‌شود؛ فقط کوکی HttpOnly بک‌اند استفاده می‌شود. ورود به نشانی صفحهٔ حساب به‌تنهایی مجوز دسترسی به اطلاعات نمی‌دهد؛ API در هر درخواست نشست را اعتبارسنجی می‌کند.

درخواست‌ها به مسیر نسبی `/api/v1/auth` می‌روند و Next با rewrite آن‌ها را به API_ORIGIN می‌فرستد. این مقدار سروری است و در bundle عمومی قرار نمی‌گیرد. تغییر API_ORIGIN در استقرار نیازمند build جدید است. WEB_ORIGIN بک‌اند باید مبدأ مرورگر باشد؛ مثلاً http://localhost:3000. این اتصال، جای تنظیم شبکه و اعتماد محدود به پراکسی در محیط واقعی را نمی‌گیرد.

## آزمون‌های آماده‌شده

پنج آزمون Playwright نوشته شده‌اند: اعتبارسنجی و خطای نبود پیامک در موبایل، ورود با ارقام فارسی و کد اشتباه و سپس صحیح، حفظ نشست بعد از refresh و خروج، بازگرداندن مهمان به ورود، ارسال مجدد و تعویض challenge، و انقضای فرم و ویرایش شماره. بعضی سناریوها در یک آزمون ترکیب شده‌اند.

مرورگر به Next واقعی روی پورت ۳۱۰۰ و از آنجا به Express واقعی روی پورت ۴۱۰۰ وصل می‌شود. MongoDB واقعی است؛ پیامک فقط در fixture تست در حافظه ذخیره می‌شود. پاسخ ورود در مرورگر mock نمی‌شود.

fixture خارج از src بک‌اند است و در build تولیدی وارد نمی‌شود. فقط با NODE_ENV=test و کلید تصادفی هر اجرا شروع می‌شود و روی loopback گوش می‌دهد. مسیرهای کنترلی /__test نیازمند همان کلید هستند و در برنامهٔ اصلی وجود ندارند. دیتابیس با پیشوند raqs_browser_test_ و نام تصادفی ساخته می‌شود؛ teardown فقط همان دیتابیس را حذف می‌کند. کوتاه‌شدن فاصلهٔ ارسال مجدد به دو ثانیه فقط برای آزمون است.

## اجرای بررسی‌ها

با Node ۲۲ و MongoDB محلی:

```powershell
npm ci
npm run format
npm run check
npm run test:integration
npx playwright install chromium
npm run test:e2e
npm run build
```

در ویندوز اگر Edge نصب است، می‌توان به‌جای دانلود مرورگر از آن استفاده کرد:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

پورت‌های ۳۱۰۰ و ۴۱۰۰ باید آزاد باشند. استفاده از سرور موجود در آزمون ممنوع شده است تا به سرویس شخصی یا دادهٔ واقعی وصل نشود. fixture و ابزارهای کنترلی آن نباید روی اینترنت منتشر شوند. خطای پاک‌سازی دیتابیس نباید نادیده گرفته شود.

اسکرین‌شات‌ها در test-results نوشته می‌شوند و وارد Git نمی‌شوند. اسکرین‌شات موبایل و دسکتاپ در اجرای موفق ۲۰۲۶-۰۹-۲۲ بازبینی شد. تست با RAQS_E2E=1 از پوشهٔ .next-e2e استفاده می‌کند تا با خروجی و قفل سرور توسعه تداخل نداشته باشد.

## وضعیت فعلی

در ۲۰۲۶-۰۹-۲۲ محدودیت اجرای قبلی برطرف شد. check، نه آزمون MongoDB، پنج آزمون مرورگر با Edge و build تولیدی موفق شدند. انتخاب پیام خطای فرم در تست به ناحیهٔ حساب محدود شد تا با اعلان داخلی Next تداخل نکند. ارسال پیامک واقعی هنوز متصل نیست.

مراجع: [Next.js rewrites](https://nextjs.org/docs/app/api-reference/config/next-config-js/rewrites)، [Playwright web servers](https://playwright.dev/docs/test-webserver).
